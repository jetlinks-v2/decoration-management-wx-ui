## 2. 本轮功能

- 登录后请求服务端可信身份：仅业主或仅员工直接进入，双身份展示选择页；有明确端别入口时优先使用该已授权身份。双身份可以在顶部切换，保留草稿确认、提交中保护，并取消旧身份请求及重建页面。
- 业主继续使用装修通知；巡检不通过进入整改页面，复用提交整改、申请复核、驳回重提及复核通过功能。
- 员工新增“任务通知”页签，验收指派和整改待复核通知可以进入具体任务。
- 收件人重新校验当前应用成员、有效员工、项目范围和对应动作权限；复核通知还检查角色。身份选择和通知链接均不能扩大服务端权限。
- 办理事务内入队、后台发送；失败重试，任务版本、指派或角色失效后取消旧员工待办。角色展开为每人独立发件项，不将“已展开”计为“已送达”。

### 接口

| 用途 | 接口 | 契约 |
| --- | --- | --- |
| 本人业务身份 | `GET /decoration/mobile/identity` | `{owner:boolean,staff:boolean}`；业主权限加本人有效房屋、任务权限加有效员工档案；目录故障仍报错 |
| 业主通知 | `POST /decoration/mobile/applications/_notifications/_query` | 沿用原分页契约、本人及应用/租户/项目范围 |
| 员工通知 | `POST /decoration/tasks/mine/notifications/_query` | 现有任务查询权限、有效员工；本人、应用/租户/项目及当前复核角色过滤 |

通知展示字段保留原契约，增加 `side`（`owner`或`staff`）及可选 `taskId`。员工任务详情沿用原任务接口，业主整改沿用原本人详情和整改接口。

### 新增通知事件

| 事件 | 收件人 | 点击位置 |
| --- | --- | --- |
| `firstTaskAssigned` | 被指派的有效员工 | 本人的首次验收任务 |
| `secondTaskAssigned` | 被指派的有效员工 | 本人的二次验收任务 |
| `rectificationRequired` | 申请业主 | 巡检整改 |
| `rectificationReview` | 指定复核角色中的有效应用员工成员，逐人核验项目及复核权限 | 对应待复核任务 |
| `rectificationPassed` | 申请业主 | 整改结果 |
| `rectificationRejected` | 申请业主 | 整改意见、修改并重提 |

既有审核、缴费、备案、首验、二验、退款流程提醒继续保留。没有回填历史业务轨迹为新通知。

## 3. APP通知跳转契约

当前发送复用公共 `SendUserNotificationCommand`，通道为 `inside-mail`，通知源为 `property-decoration`。没有接入新的手机系统推送通道。

公共通知 `detail` 字段为：

```json
{
  "applicationId": "真实装修应用ID",
  "decorationId": "装修申请ID",
  "side": "staff",
  "step": "task",
  "taskId": "具体任务ID",
  "url": "/decoration-h5/?applicationScope=应用ID&side=staff&decorationId=申请ID&step=task&taskId=任务ID"
}
```

业主通知 `side=owner`；整改使用 `step=rectification`。一般流程提醒按原 `apply/pay/permit/first/second/refund` 步骤定位，非任务通知可以不含 `taskId`。

APP宿主应先根据 `applicationId` 选择真实应用，再将定位信息映射至本模块路由，例如：

```text
/applications/decoration-app/staff?decorationId=申请ID&step=task&taskId=任务ID
/applications/decoration-app/owner?decorationId=申请ID&step=rectification
```

H5模块读取自己的路由query，不读取宿主外层网页URL，不从URL接收token、用户或租户身份。通知链接只定位对象；请求与操作继续使用宿主提供的当前应用认证。收到非当前身份通知时，不得以切换界面代替资格核验。

独立H5保留 `/decoration-h5/?applicationScope=真实应用ID&side=...` 入口。不要把独立登录凭据带入APP组合入口。

## 5. 主会话页面验收顺序

1. 更新并启动配套装修后端，再启动H5。确认 `/decoration/mobile/identity` 命中本轮后端，并确认 `pd_notification` 新增逻辑字段 `recipientSide/taskId/taskVersion/roleId/dispatcherId` 已由现有实体映射完成建表/更新。旧通知空端别按业主兼容。
2. 分别用仅业主、仅员工、双身份账号进入。双身份无明确入口时出现选择页；有入口偏好时可在顶部切换。未保存草稿应确认，提交中禁止离开；切换后不显示上一身份的数据。没有真实档案或权限的身份不能通过URL强行进入。
3. 创建新申请，完成全部审核，核对业主收到缴费提醒并跳到对应申请步骤；继续缴费、备案、首验、二验和退款，核对原有下一步提醒。历史通知不应因本次升级被批量补发。
4. 指派首验/二验给有应用和项目权限的员工。核对员工任务通知只展示本人任务，点击能到具体任务；换账号、换项目、移除角色或应用成员后，不应继续取得无权数据或收到旧待办。
5. 巡检提交不通过，业主从整改通知进入填写整改说明/附件并申请复核；复核人员从任务通知进入，驳回后业主补充重提，最后通过。核对按钮、结果和通知对象一致。
6. 在隔离测试中验证目录/通知服务故障：业务正常落库，通知稍后重试；角色多人时每人独立去重，旧任务版本不补发。不要改数据库状态制造业务成功。
7. APP会话另外验证真实应用选择、公共消息中心读取、点击路由、前后台/冷启动、未登录恢复和返回。系统通知、角标、离线推送及真机送达需要宿主通道实测；站内通知列表或入队成功不能作为这部分通过依据。
